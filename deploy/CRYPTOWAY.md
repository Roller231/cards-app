# Cryptoway: оплата карт в USDT

## Расчёты

- Пополнение карты: сумма на карту × (1 + `CRYPTOWAY_TOPUP_MARKUP_PERCENT` / 100).
  При 3,6%: $100 → 103,60 USDT, $50 → 51,80 USDT.
- Выпуск: рублёвая цена из админки с реферальной скидкой / исходный индекс
  Bitbanker. Округление вверх до 0,01 USDT. Комиссии СБП и 210 ₽ отсутствуют.
- Цена и курс фиксируются в серверном расчёте, счёт действует 30 минут.
- Комиссию Cryptoway платит ProntoPay. Ответ API должен содержать нулевые
  `fee_split_percent` и `markup_percent`, а `payer_amount` должен точно
  совпадать с согласованной суммой. При расхождении счёт не показывается.

## Конфигурация

Backend получает из `/opt/prontopay/backend/.env`:

```dotenv
CRYPTOWAY_API_URL=https://api.cryptoway.com
CRYPTOWAY_PROJECT_ID=
CRYPTOWAY_SECRET_KEY=
CRYPTOWAY_CALLBACK_KEY=
CRYPTOWAY_ENABLED=true
CRYPTOWAY_TOPUP_MARKUP_PERCENT=3.6
CRYPTOWAY_INVOICE_MINUTES=30
CRYPTOWAY_PAY_WITHOUT_KYC=true
PUBLIC_BASE_URL=https://prontopay.pro
```

Секретный ключ подписи API и callback key — разные. В git и админку они
не попадают. Первый запрос привязывает ключ к IP, поэтому его выполняют
с прод-сервера. Runtime env исключён из контекстов Docker.

Админка: «Криптооплаты» — счета и результаты операций; «Настройки → Оплата
USDT» — доступность способа и наценка. Изменение defaults не перекрывает
существующее значение настройки в БД.

## Сети

Показываются только активные, невиртуальные символы USDT из API Cryptoway.
На 10.11.2026: TRC20, ERC20, BEP20, TON, Solana, Polygon, Arbitrum.
Минимум проверяется по актуальному тарифу выбранной сети.

## Подтверждение и выполнение

Webhook: `https://prontopay.pro/api/webhooks/cryptoway`.
HMAC-SHA256 проверяется отдельным callback key; окно timestamp ±15 секунд.
Вложенные уведомления invoice и плоские deposit подписаны по-разному.
Webhook доступен во время техработ.

Статус callback не считается доказательством оплаты. Backend перечитывает
счёт и депозиты через API, сверяет владельца заказа, валюту, сеть и сумму.
Только `executed` и полностью подтверждённая сумма запускают услугу.
Недоплата, AML-блокировка и деньги на просроченном счёте не запускают выпуск.
Переплата видна пользователю и требует возврата разницы через поддержку.

Счета и привязка к заказам сохраняются в `cryptoway_payments`. Создание
счёта и запуск услуги предваряются сохранённой в БД блокировкой состояния.
Повторный callback не запускает второй выпуск или перевод. После таймаута
создания счёт ищется по `external_id`; POST автоматически не повторяется.
Неопределённый ответ провайдера карты передаётся на ручную проверку.
Окончательный отказ по связанному заказу возвращает оплаченную сумму на
внутренний USD-баланс ровно один раз. Неизвестный результат не возвращается
автоматически, поскольку операция могла фактически пройти.

Опрос раз в 30 секунд восстанавливает обработку после пропущенных webhook
и перезапуска. Платные операции выполняют существующие сервисы карт.

## KYC

Pay (Rocketpay): выпуск и пополнение через Cryptoway доступны без KYC
пользователя при `CRYPTOWAY_PAY_WITHOUT_KYC=true`. Rocketpay использует
пул собственных проверенных держателей; паспорт пользователя не передаётся.
Расчёт и счёт возвращают `kyc_required=false`, интерфейс явно сообщает об этом.
Исключение относится к криптооплате Pay.

Online: выпуск и пополнение требуют успешного KYC с данными паспорта при
любом способе оплаты — USDT, СБП и внутренний баланс. Проверки выполняются
до списания/создания счёта, а также в сервисе выполнения операции.

Контрольный клиент
`pp_crypto_probe_20261110` создан без паспорта: регистрация успешна, но
проверка выпуска Online вернула `IDENTIFICATION_DOCUMENT_ABSENT`.
Этот результат не подтверждает поддерживаемый выпуск без паспортных данных.
Сценарий без KYC для Online требует уточнения настройки продукта у O-Plata.

## Проверка

Из `backend`: `venv/Scripts/python.exe -m unittest discover -s tests -v`.
Frontend: `npm run build`.
Проверять реальные счета следует с сервера, без повторения POST при таймауте.
Создание и отмена неоплаченного счёта не проверяют on-chain зачисление:
для полного боевого теста нужен отдельный перевод и подтверждение сети.
